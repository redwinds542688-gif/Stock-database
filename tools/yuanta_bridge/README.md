## 安裝與測試

```bash
sudo bash install.sh                       # 裝環境(/opt/yuanta_bridge)
# 放 SDK 到 /opt/yuanta_bridge/sdk、憑證到 /opt/yuanta_bridge/cert,編輯 /opt/yuanta_bridge/bridge.env
sudo -u yuanta /opt/yuanta_bridge/venv/bin/python /opt/yuanta_bridge/yuanta_bridge.py test 2330
```

`test` 會連線、登入、訂閱 2330,印 60 秒逐筆成交。確認:登入回 `0001`、有逐筆進來、成交量單位(張或股,決定 `VOL_MULT`)。

## Worker 設定

在 Cloudflare Worker(twse-proxy)→ Settings → Variables and Secrets 加一個密鑰 **`YT_PUSH_KEY`**(自己產生一串亂碼,例如 `openssl rand -hex 24`),
同一串填到主機 `bridge.env` 的 `PUSH_KEY`。

- `POST ?ybars=push`(帶 `X-Push-Key`):中繼程式送 1 分 K,一分鐘一個 KV 鍵 `ybar:日期:時分`
- `GET ?ybars=today`(或 `YYYY-MM-DD`,可加 `&codes=2330,2409&since=10:00`):讀回來,格式同 `?bars`

## 上線順序

1. 測試環境(UAT)用元大公開測試帳號跑 `test`,確認程式和元件正常
2. 正式環境(PROD)用自己的帳號跑 `run` 一天,收盤後拿 `?ybars=` 和 `?bars=`、元大看盤軟體逐分鐘比對
3. 準了再改手機讀 `?ybars=`(那時再改 app.html;雲端快照可以停掉,省 KV 寫入)

## 限制(元大文件「使用限制說明」)

- 單次訂閱最多 200 檔、一秒最多 10 次;每條連線訂閱上限 2,000 檔
- 登入失敗後每 4 秒最多重試 1 次、一天最多登入 1,000 次(程式斷線重連間隔 10~60 秒)
- 呼叫超量會暫停 1 分鐘;一小時被暫停 10 次會停用帳號的 API

**安全**:帳號、電子密碼、憑證密碼只放在主機的 `bridge.env`(權限 600),不要貼到對話或 GitHub。

## 一次一單自動交易(trader.py)

2026-10-22 使用者:「真的接通 可以先試 一次只掛一單 成交後才能繼續」→「先寫好 預設測試環境」。

- **訊號**:手機的通知(雲端紀錄 `?log=get`,每 3 秒看一次)。進場通知 → 進場;同一檔的平倉通知 → 出場。啟動時當天已有的通知不算。
- **一次一單**:空閒 → 進場中 → 持倉中 → 平倉中 → 空閒;不是空閒時其他訊號一律不接(只記錄)。
- **快速出場**:通知裡的停利 / 停損價由程式用元大逐筆成交盯,碰到就送平倉單(約 1 秒內)。
- **13:20 先取消全部掛單,再平倉**(使用者:「13:20 就要先取消所有掛單 再進行贖回動作」):程式的條件單 / 委託先取消 → 查元大全部還掛著的委託和
  五種條件單(停損利、移動鎖利、二擇一、母子單、多條件),通通取消(含手動的)→ 再查確認(最多 3 次)→ 用最新成交回報算還沒沖銷的部位,
  漲停買回 / 跌停賣出 ROD。這段失敗的話 13:21 程式自己強制平倉當備援。`TRADE_CANCEL_ALL=0` 可關掉(改回直接平倉)。
- **13:20 強制平倉**(使用者:「其實 1:25 到 1:30 才掛單很危險」):13:25~13:30 是收盤集合競價,價格要等 13:30 撮合才知道 →
  `TRADE_FORCE_EXIT`(13:20)還在逐筆撮合時就掛漲停買回 / 跌停賣出 ROD,馬上照市價成交;新進場只到 `TRADE_LAST_ENTRY`(13:10)。
  萬一 13:25 後還沒平完(使用者:「必須掛漲停價(做空)或跌停價(做多)贖回,1:30 一定會成交(除非漲停或跌停)」):
  集合競價不收市價 / IOC / FOK → 一律漲停 / 跌停 ROD,13:30 撮合時排最前面成交(鎖漲停 / 跌停例外)。
- **13:22 / 13:23 / 13:24 複查三次**(使用者:「13:23 分要再確認一次 還有沒有未沖銷的股票」→「確認三次 以保安全」):每次查元大今天的成交回報算每檔淨部位,
  先扣掉已經掛著還沒成交的平倉委託(避免上一次的補單還沒成交又重複下單,變成反向部位),不夠才補——
  程式的部位沒平完 → 再掛漲停 / 跌停 ROD;**在投資先生手動交易、還沒平倉的也一樣平**(使用者:「平倉也是一樣 要包含投資先生手動交易尚未平倉的股票」):
  手動空單掛漲停買回、手動多單掛跌停賣出。部位只算「今天的成交」,之前買進留著的庫存不會被賣掉。
  `TRADE_RECHECK_CLOSE` 預設 all;可改 short(只平手動空單、多單只提醒)/ none(都只提醒)。每一筆都發提醒到手機「今日監控紀錄」。
- **下單方式**:進場 = 限價 + IOC(讓 `TRADE_SLIP_TICKS` 檔,沒成交就不追)。
  **平倉 = 空單買回掛漲停、多單賣出掛跌停(ROD)**(使用者:「直接掛漲停價贖回,不管股價怎麼跑都會在第一時間平倉」):
  照價格優先從最好的價位開始成交,實際成交價 = 當下市價;用 ROD 是因為價格穩定措施(暫緩撮合)時 IOC / 市價會失效,ROD 會留著等撮合。
- **進場當下預掛停損(元大條件單)**(使用者:「在股票交易啟動當下 直接預掛停損是最好方式」):進場成交後馬上在元大主機掛**二擇一條件單(OCO)**——
  停損、停利兩個成交價條件,哪個先到就送漲停買回 / 跌停賣出(ROD),另一個取消。程式或網路斷了元大照樣平倉。
  OCO 在的時候,程式自己的停利停損只記錄不下單;程式因為手機平倉通知 / 13:25 要平倉時,**先刪 OCO 再送平倉單**;
  萬一兩邊同時成交(多平了),程式偵測到馬上反向補回。OCO 掛失敗就改由程式自己盯。`TRADE_BROKER_STOP=0` 可關掉。
  空單用條件單的「現股買進」買回:使用者說明按不按「沖」都可以贖回,所以可以沖銷。
- **以元大回報為準**:即時回報 51(成交)才算成交,用自訂編號(BasketNo)對單。
- **保護**:每筆張數、一天筆數、當天虧損上限、現價離訊號價太遠不追、`touch /opt/yuanta_bridge/STOP` 緊急停止(不再進場,有部位照樣平)。
- **預設關閉**:`TRADE_ENABLE=1` 才會下單;正式環境還要 `TRADE_ALLOW_PROD=1`。
- **啟動時接回部位**(使用者:「加 啟動時接回部位」):程式當天第一次連上元大時,查今天的委託成交回報和有效的二擇一條件單,
  算出還沒平的部位;是程式開的(委託的 BasketNo 是 T 開頭)就接回來管理(13:25 強制平倉、手機平倉通知照常),條件單在就沿用、不在就用手機通知的停利停損重掛。
  今天已做的筆數、已實現損益也算回來(一天筆數 / 虧損上限照樣有效)。手動在投資先生做的部位不接回(盤中不管,13:20 收盤平倉時照樣平掉)。
- **只做整張**(使用者:「都以張為單位 沒有在買賣零股的」):下單一律整股(APCode 0)、數量單位是張;回報的股數除以 1000 換成張。

上線順序:測試環境 `order-test` 試下單回應 → 測試環境 `TRADE_ENABLE=1` 跑幾天(元大測試環境依委託書號尾碼模擬全成交 / 不成交 / 部分成交 / 價穩失效)
→ 正式環境 1 張、一天 3 筆跑一兩週。使用者已有當沖資格(2026-10-22)。做空要用「沖」:元大 App 下單畫面要按「沖」亮起來才能賣出做空(使用者截圖 2026-10-22,時碩「可現股當沖、平盤下可放空」),
對應 API 的委託種類 `9` 現股當沖委託控管 → `TRADE_TYPE_SHORT=9`,空單進場賣出和買回平倉都用 9。
做多只要「現股」亮起來(使用者 2026-10-22)→ `TRADE_TYPE_LONG=0`,買進、賣出都用 0;多單的元大條件單平倉是「現股賣出」,和進場一致,沒有疑問。
空單買回:使用者說明「在贖回裡 按不按 沖 亮起來與否 都可以贖回」(2026-10-22)→ 條件單(OCO)的「現股買進」可以沖銷「沖」賣出的空單,
進場就預掛停損做多做空都適用。第一次正式交易時看委託成交回報 / 元大 App 的當沖沖銷,確認那筆有被算成當沖。
有些股票不能現股當沖或平盤下不能放空(例如處置股),元大會拒絕委託,程式收到拒絕就回空閒、不重試。

限制:手機通知經過雲端紀錄,KV 列表最慢可能延遲約一分鐘,所以「進場」可能比通知晚;「出場」的停利停損由這裡即時盯,不受影響。

## 手機即時價走元大(選用,預設關閉)

2026-10-22 使用者:「手機即時價也要改用元大」。

```
手機 ──?codes──▶ Worker ──先問──▶ cloudflared 通道 ──▶ 本機報價服務(127.0.0.1:8787,quotes.py)
                     └─ 沒登記 / 連不上 / 超過 1.5 秒 / 有股票元大沒有 / 盤中 60 秒沒更新 ──▶ 照舊問證交所
```

- 手機 App 不用改:Worker 回的格式和證交所一樣(c、z、v、y、o、h、l、b、a、t、d)。
- 開啟:`bridge.env` 設 `QUOTE_ENABLE=1`,裝 cloudflared(install.sh 最後有指令)並啟動 `cloudflared-quote` 服務。
  通道網址每次重開會變,中繼程式每分鐘自動登記到 Worker(`?yquote=register`);`?yquote=status` 可以看目前網址和狀態。
- **安全**:這會讓主機上的報價服務透過 Cloudflare 通道對外;服務只聽 127.0.0.1、只回報價(唯讀)、要帶和 `PUSH_KEY` 一樣的金鑰才回資料。
  不想對外就維持 `QUOTE_ENABLE=0`,即時價照舊走證交所。
- 中繼程式盤中才啟動的話,累計量只從啟動那刻算(價格不受影響)。
