## 二、架構

```
元大 SPARK API(正式環境)
   │ 逐筆成交 / 下單 / 回報
   ▼
家裡桌機 Windows(中繼程式 yuanta_bridge.py,工作排程背景執行)
   │ 第一階段:1 分 K 只存本機 CSV(C:\Yuanta\bridge\bars_yuanta\日期.csv)
   │ 之後:POST ?ybars=push → Worker(存 Durable Object Hub)
   ▼
Cloudflare Worker twse-proxy(https://twse-proxy.redwinds542688.workers.dev)
   ▼
手機 App(目前仍讀雲端 K ?bars;之後改讀元大 ?ybars,沒有就退回雲端 K)
```

- 自動交易(之後):桌機的 `trader.py` 每 3 秒讀 Worker `?log=get`(手機發的進出場通知)→ 一次一單下單。
- 手機不能當連線主機:元大元件只有 Windows / Mac / Linux 版,Android 也會把背景程式停掉。
- 桌機沒開:手機自動用雲端 K(雲端 K 快照繼續保留當備援)。

## 八、自動交易(trader.py)設計重點(**目前關閉**)

- 跟手機通知(`?log=get`,判一 / 判二 / 判三)「一次一單」:空閒 → 進場中 → 持倉中 → 平倉中;不是空閒時其他訊號不接。
- 進場:限價 + IOC(讓 2 檔);做多委託種類 0(現股)、做空 9(現股當沖 = App 的「沖」);平倉:空單掛漲停買回、多單掛跌停賣出(ROD)。
- 進場成交後在元大主機掛二擇一條件單(停損 + 停利);平倉前先刪條件單。
- **13:10** 最後進場;**13:20** 先取消全部掛單(委託 + 五種條件單,含使用者在投資先生手動掛的)→ 確認後平倉;13:21 備援強制平倉。
- **13:22 / 13:23 / 13:24** 複查三次未沖銷部位(扣掉還掛著的平倉委託);**投資先生手動交易、今天還沒平倉的也一起平**(`TRADE_RECHECK_CLOSE=all`;之前留的庫存不動)。
- 啟動時接回程式開的部位(BasketNo 以 T 開頭)。
- 預設:每筆 1 張、一天最多 3 筆、當天虧損 3,000 停止進場、`TRADE_ALLOW_PROD=0`(正式環境下單總開關)。
- 緊急停止檔 `TRADE_STOP_FILE` 預設是 Linux 路徑,**Windows 要改成例如 `C:\Yuanta\bridge\STOP`**(還沒改)。

**開自動交易前的順序**:① `win_order_test.py` 掛單取消 → ② 手動真的成交 1 張再賣 → ③ 開自動交易但 1 張、一天 1~2 筆、虧損上限 3,000 → ④ 跑一兩週再放寬。

## 十、注意事項

1. **同一個元大帳號不要同時登入兩支程式**:中繼程式盤中在背景跑時,不要再執行 `win_test.py`(`win_order_test.py` 會自己先暫停排程)。

3. 每次修改推送完成後,回覆最後寫「已推送完成」。
4. 改 app.html:最上面加變更紀錄、`<meta name="app-build">` 往上加(年月日時分)、複製到 `android/app/src/main/assets/app.html`。
5. 判別式(判一二三)由另一個對話在調整;改判別式要使用者明確說「改」,且 App 和模擬器要 0 差異。
6. 疑難排解:
   - 開機出現「Reboot and Select proper Boot device」→ 開機按 F11 選 Windows Boot Manager,或 BIOS Boot Option #1 改回 Windows Boot Manager。
   - 登入 20 秒沒回應 → 確認程式有等「交易主機 Is Connected」再登入。
   - 工作排程要 Windows 密碼 → 是微軟帳號密碼(不是 PIN)。
   - 下載到舊版程式 → 網址改用 commit 版本號。
